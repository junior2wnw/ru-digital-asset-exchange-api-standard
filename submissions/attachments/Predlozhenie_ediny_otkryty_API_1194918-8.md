# Предложение О Едином Открытом API-Профиле Для Инфраструктуры Обращения Цифровой Валюты

Приложение к обращению по законопроекту N 1194918-8

## 1. Краткая Проблема

При создании инфраструктуры обращения цифровой валюты существует риск технической фрагментации: каждый участник рынка может реализовать собственный закрытый API для заявок, сделок, балансов, статусов исполнения, рыночных данных, ошибок, лимитов, отчетности и wallet-операций.

Это приведет к удорожанию интеграций, росту операционных рисков, усложнению надзора, задержкам запуска отечественного программного обеспечения и технологической зависимости рынка от набора частных несовместимых интерфейсов.

## 2. Предлагаемое Решение

Закрепить принцип единого открытого API-профиля для участников инфраструктуры обращения цифровой валюты.

Открытой должна быть спецификация API, а не доступ к данным. Доступ к клиентским данным и операциям должен оставаться защищенным, авторизованным и соответствующим требованиям информационной безопасности, банковской, коммерческой, налоговой и иной охраняемой законом тайны.

Технические требования к API-профилю целесообразно устанавливать нормативным актом Банка России. В требования следует включить:

- REST API для команд и запросов;
- WebSocket API для рыночных данных;
- WebSocket API для приватных клиентских событий;
- FIX-compatible профиль для профессиональных участников;
- единую модель заявок;
- единую модель сделок;
- единую модель балансов и цифровых счетов;
- единую модель ошибок;
- единую модель комиссий и лимитов;
- единые статусы wallet-операций;
- требования к аутентификации, подписи запросов, idempotency и audit trail;
- sandbox/testnet;
- conformance tests и порядок подтверждения совместимости.

## 3. Предлагаемая Поправка

Возможная редакция нормы для юридико-технической доработки:

> Участники инфраструктуры обращения цифровой валюты, осуществляющие профессиональную деятельность в соответствии с настоящим Федеральным законом, обязаны обеспечивать программное взаимодействие с клиентами, иными участниками инфраструктуры и сервисными провайдерами посредством открытого программного интерфейса по единым требованиям.
>
> Требования к открытому программному интерфейсу, включая форматы данных, порядок аутентификации, требования к криптографической защите, порядок передачи сведений о заявках, сделках, балансах, цифровых счетах, лимитах, статусах исполнения, рыночных данных, ошибках, событиях контроля операций, wallet-операциях и отчетности, устанавливаются нормативным актом Банка России.
>
> Участники инфраструктуры обращения цифровой валюты обязаны обеспечить совместимость своих информационных систем с указанным интерфейсом, в том числе в тестовом контуре, до начала оказания соответствующих услуг клиентам.
>
> Банк России вправе устанавливать порядок подтверждения соответствия программных интерфейсов участников инфраструктуры обращения цифровой валюты единым требованиям, включая использование тестовых наборов, эталонных сценариев и средств автоматизированной проверки.
>
> Документация открытого программного интерфейса подлежит опубликованию в машиночитаемом виде, за исключением сведений, составляющих охраняемую законом тайну или создающих риски для информационной безопасности.

## 4. Почему Это Нужно Государству

Единый API-профиль создает техническую основу для надзора, аудита, отчетности и анализа операционных рисков. Он позволяет не только подключать участников рынка, но и проверять качество их интеграций через автоматизированные conformance tests.

Для государства это означает:

- меньшую зависимость от закрытых частных интерфейсов;
- более прозрачную инфраструктуру;
- меньший риск технических ошибок при исполнении заявок и учете сделок;
- более быстрый запуск отечественного программного обеспечения;
- возможность формировать единые требования к тестовым контурам.

## 5. Почему Это Нужно Рынку

Для бирж, брокеров, банков, депозитариев, wallet-провайдеров, сервисных провайдеров и разработчиков единый API-профиль снижает стоимость интеграций. Вместо набора несовместимых адаптеров участники получают общий технический словарь и проверяемую модель совместимости.

Это особенно важно для:

- spot trading;
- margin trading;
- futures и perpetual futures;
- options и swaps;
- wallet, deposits, withdrawals и internal transfers;
- custody и subaccounts;
- market data;
- private client events;
- reporting и audit trail.
