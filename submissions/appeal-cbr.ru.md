# Обращение В Банк России

Тема:

`Предложение о единых требованиях к API инфраструктуры обращения цифровой валюты`

Текст обращения:

Уважаемые коллеги!

Прошу рассмотреть предложение о разработке единых требований к открытому API-профилю для участников инфраструктуры обращения цифровой валюты в связи с рассмотрением законопроекта N 1194918-8 и возможной подготовкой связанных подзаконных нормативных актов.

Предложение не предполагает закрепления конкретной частной библиотеки или поставщика программного обеспечения. Речь идет об открытой спецификации программного интерфейса, тестовом контуре и автоматизированной проверке совместимости. Доступ к данным и операциям должен оставаться защищенным, авторизованным и соответствующим требованиям информационной безопасности.

## Предлагаемый Подход

Считаю целесообразным предусмотреть единый API-профиль, требования к которому утверждаются Банком России и включают:

1. REST API для команд и запросов;
2. WebSocket API для рыночных данных;
3. WebSocket API для приватных событий клиента;
4. FIX-compatible профиль для профессиональных участников;
5. единую модель заявок;
6. единую модель сделок;
7. единую модель балансов и цифровых счетов;
8. единую модель ошибок;
9. единую модель комиссий и лимитов;
10. единые статусы wallet-операций, депозитов, выводов и внутренних переводов;
11. требования к аутентификации, подписи запросов, idempotency и audit trail;
12. sandbox/testnet и conformance tests.

## Зачем Это Нужно Банку России И Рынку

Без единого API-профиля у участников рынка могут возникнуть несовместимые форматы заявок, сделок, балансов, статусов исполнения, лимитов, ошибок, отчетности, рыночных данных и событий контроля операций. Это усложнит надзор, аудит, анализ инцидентов и подключение новых участников.

Единые требования к API позволят:

1. снизить операционные риски;
2. упростить контроль совместимости участников;
3. ускорить подключение российских брокеров, банков, разработчиков и сервисных провайдеров;
4. повысить качество тестирования до запуска клиентских услуг;
5. обеспечить единые технические условия для trading, wallet, custody, derivatives и отчетности;
6. сформировать независимый conformance-процесс.

## Предлагаемые Элементы Нормативного Профиля

Прошу рассмотреть возможность включения в технические требования следующих элементов:

- открытая публикация API-документации в машиночитаемом виде;
- обязательный тестовый контур до начала оказания услуг клиентам;
- автоматизированные проверки совместимости;
- единая модель ошибок и кодов отказа;
- idempotency key для торговых и wallet-команд;
- раздельные scopes API-ключей;
- требования к подписи приватных запросов;
- требования к WebSocket private events;
- единый формат отчетности и событий контроля операций;
- compatibility levels для поэтапного внедрения.

Готов предоставить для обсуждения draft технического API-профиля, OpenAPI/JSON Schema, mock exchange, conformance tests и reference SDK. Указанные материалы могут использоваться как нейтральная отправная точка для пилота и не предполагают обязательного использования конкретной библиотеки.

Прошу рассмотреть предложение при подготовке требований к инфраструктуре обращения цифровой валюты и, при наличии возможности, направить его в профильное подразделение Банка России, ответственное за регулирование финансовых рынков и цифровых активов.
