# Как продвинуть именно свою библиотеку

Главный принцип: нельзя начинать с требования "обяжите всех использовать мою библиотеку".

Правильная стратегия: продвигать открытый стандарт, а свою библиотеку сделать лучшей reference implementation.

## Шаг 1. Оформить стандарт

Возможные названия:

- **RU Digital Asset Exchange API Standard**;
- **SpreadX Unified Crypto Market API**.

Состав стандарта:

1. REST API.
2. WebSocket market data.
3. WebSocket private events.
4. FIX-compatible profile для профессиональных участников.
5. Единая модель ордеров.
6. Единая модель сделок.
7. Единая модель балансов.
8. Единая модель ошибок.
9. Единая модель комиссий.
10. Единая модель лимитов.
11. Sandbox/testnet.
12. Conformance tests.

## Шаг 2. Сделать open-source SDK

Минимальный пакет:

- Python SDK;
- TypeScript SDK;
- OpenAPI schema;
- JSON Schema;
- Postman collection;
- conformance test suite;
- reference mock exchange.

Цель SDK: стать самым простым способом внедрить стандарт.

## Шаг 3. Написать white paper

Название:

**Единый открытый API для регулируемого рынка цифровой валюты РФ**

Структура:

1. Проблема фрагментации API.
2. Риски для ЦБ и участников.
3. Международные аналоги.
4. Предлагаемая архитектура.
5. Требования безопасности.
6. Модель совместимости.
7. План внедрения за 6 месяцев.
8. Выгоды для государства, бирж, брокеров и пользователей.

## Шаг 4. Идти не только в Госдуму

Адресаты:

1. Комитет Госдумы по финансовому рынку.
2. Банк России.
3. Минфин.
4. Минцифры.
5. Росфинмониторинг.
6. РАКИБ.
7. Ассоциация ФинТех.
8. Потенциальные российские биржи, брокеры, банки и инфраструктурные провайдеры.

## Самая сильная юридическая формула

Нужно добиваться не монополии библиотеки, а одного из трех:

| Цель | Реалистичность | Выгода |
| --- | --- | --- |
| Единый API в законе | Средняя | Высокая |
| Единый API в акте ЦБ | Высокая | Очень высокая |
| SDK как open-source reference implementation | Высокая | Максимальная для входа на рынок |

Лучший путь:

1. Закон говорит: "должен быть единый открытый API".
2. Банк России утверждает требования.
3. Проект приносит готовый стандарт, SDK и тесты.
4. Рынок начинает использовать реализацию, потому что она уже готова.

## Что делает этот репозиторий

Этот репозиторий сразу закрывает технический минимум:

- описывает стандарт;
- публикует white paper;
- дает OpenAPI и JSON Schema;
- дает Python и TypeScript SDK;
- дает mock exchange;
- дает conformance tests;
- показывает путь внедрения от L0 до L4.

Так проект выглядит не как просьба о привилегии, а как готовая инфраструктура для рынка.
